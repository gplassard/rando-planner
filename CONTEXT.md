# Rando Planner - Project Context

## Purpose
Hiking itinerary planner for France. Users select train stations as start, waypoints, and end points on an interactive map. Combines public transport access with hiking routes.

## Domain Terminology

- **Station**: Train station. Has id, label, city, lineIds, location (LatLng)
- **HikingRoute**: Hiking trail with id, name, from, to, bounds (LatLngBounds). Full geometry is served as vector tiles, not stored per-route in the app.
- **Itinerary**: start (Station), end (Station), steps (Station[])

## Architecture

Map-first UI (wireframes v1): a full-screen Leaflet map with floating overlays —
`SearchBar` (the only way to center the map: gare or sentier), `Timeline`
(itinerary steps pinned to the bottom), `RecapPanel` (sliding panel on the right),
`ItinerariesDrawer` (« Mes itinéraires », left drawer, localStorage).

Stations loaded from `data/prepared/stations.json`; the route search index is
lazy-fetched from `data/prepared/hiking-routes-index.json`. Hiking route geometry
rendered from `data/prepared/hiking-routes.pmtiles` (PMTiles vector tile layer, see
`docs/adr/2026-10-31-hiking-routes-geometry-pmtiles.md`): trace at every zoom, route
names labeled along the line and hover tooltip (name, from → to) from zoom 11.
Gare markers are only drawn from zoom 11 (below that ~3000 stations are unreadable).
State managed via React hooks in the App component.

## Data Pipeline

Raw datasets are downloaded and preprocessed by the pipeline in `scripts/data/` (`pnpm run data`, run weekly by the `update-data` GitHub Actions workflow, which commits refreshed data to `main` and triggers a website deploy):

- Hiking routes: magOSM WFS extract of OpenStreetMap hiking routes
- Train stations: SNCF "liste des gares" export

Outputs consumed by the app:

- `data/prepared/stations.json`: stations open to travellers, aggregated by UIC code
- `data/prepared/hiking-routes.pmtiles`: full geometry of all hiking routes as a PMTiles
  archive (generated by `scripts/data/tiles.ts` with tippecanoe, layer `hiking_routes`)
- `data/prepared/hiking-routes-index.json`: minified id/name/from/to/bbox route index,
  lazy-fetched by the app for the sentier search (kept out of the JS bundle)

Other pipeline outputs (not imported by the app): `data/small_database.json` (route
metadata with bboxes), `data/small.json` (sample), `data/database.json` (gitignored).

Raw downloads land in `data/raw/` (gitignored) and are never committed.

## File Layout

```
src/
├── model/          # Domain types
├── lib/            # Pure helpers: search, itineraryStorage (localStorage)
├── components/     # Map, SearchBar, Timeline, RecapPanel, ItinerariesDrawer
├── hooks/          # useStations, useItinerary, useHikingRoutesIndex, useSavedItineraries
└── App.tsx         # Root

scripts/
└── data/           # Data pipeline: fetch, prepare, tiles, pipeline entrypoints

data/
├── raw/            # Downloaded raw datasets (gitignored)
├── prepared/stations.json
├── prepared/hiking-routes.pmtiles
├── prepared/hiking-routes-index.json
└── small_database.json
```

## Data Format

JSON: coordinates are [lng, lat]. Leaflet: LatLng(lat, lng), LatLngBounds(southWest, northEast).
